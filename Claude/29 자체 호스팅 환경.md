# 29 자체 호스팅 환경

허브: [[Claude]] · 관련: [[15 웹과 모바일]](클라우드 세션·Claude Code on the web) · [[17 클라우드 프로바이더]] · [[18 보안과 샌드박스]] · [[05 권한]] · [[09 훅]] · [[13 자동화와 스케줄링]](Remote Control과의 구분)

> [!note] 공개 베타
> 자체 호스팅 환경은 Team·Enterprise 플랜 공개 베타이며 기본 off. [Owner/admin]이 [**Cloud environments** admin 페이지](https://claude.ai/admin-settings/cloud-environments)에서 **Allow self-hosted environments**를 켜야 하고, 조직에 [Claude Code on the web]([[15 웹과 모바일]])이 활성화돼 있어야 한다. [Zero Data Retention]([[18 보안과 샌드박스]])과는 병행 불가.

**클라우드 세션**(claude.ai·모바일·데스크톱·`claude --cloud`·[[13 자동화와 스케줄링|scheduled routines]]에서 시작하는, 개발자 머신이 아닌 곳에서 도는 세션)은 기본적으로 Anthropic 인프라에서 실행된다. 자체 호스팅 환경은 그 실행 위치를 **조직이 운영하는 인프라**로 옮긴다 — 개발자 경험은 그대로이고 세션이 사설망 안에서 돌 뿐이다. 터미널·IDE에서 도는 일반 세션은 원래도 개발자 머신에서 실행되므로 영향 없음. 로컬 머신을 상시 켜두고 다른 기기에서 조종하고 싶을 뿐이라면 [[13 자동화와 스케줄링|Remote Control]](Pro·Max에서도 가능)이 더 맞는다.

## 1. 환경·러너·세션 모델 (self-hosted-environments)

세 요소로 구성된다:

- **환경(Environment)**: claude.ai admin 설정에서 만드는, 러너 집합을 묶는 이름있는 목적지. API·메트릭에서는 여전히 `pool`(`ccpool_...` ID)로 불린다.
- **러너(Runner)**: 조직 네트워크 안 호스트에서 도는 프로그램. 셀프호스팅 CI 러너와 같은 개념 — 세션을 claim해 리포를 clone하고 Claude Code 프로세스를 실행.
- **세션(Session)**: 개발자가 시작한 Claude Code 작업 1건.

개발자가 클라우드 세션을 시작하면 환경 피커에 Anthropic 호스팅 환경과 나란히 조직 환경이 뜬다. 선택 시 Anthropic 제어 플레인이 세션을 그 환경 큐에 놓고, 러너가 claim해 리포를 clone하고 자식 Claude Code 프로세스를 스폰한다. 러너는 조직 git 호스트에 설정된 자격증명으로 인증하며, Anthropic으로 가는 트래픽(큐 폴링·이벤트 스트림·모델 추론)은 전부 `api.anthropic.com`으로의 **아웃바운드 HTTPS뿐** — Anthropic이 조직 네트워크로 들어오는 연결은 없다.

### 왜 자체 호스팅인가

대부분 팀은 인프라 유지 부담이 없는 Anthropic 호스팅 환경이 낫다. 자체 호스팅은 다음이 필요한 팀을 위한 것이고, 대가로 러너 이미지 빌드·플릿 운영·네트워크 통제를 직접 떠안는다:

- **네트워크 접근**: 세션이 조직 네트워크 안에서 돌아 내부 서비스·DB·레지스트리에 공개 노출 없이 접근.
- **커스텀 툴링**: 러너 이미지에 컴파일러·SDK·내부 CLI를 미리 설치.
- **컴플라이언스**: 리포 체크아웃·빌드 아티팩트가 조직 인프라에 남음(대화 내용 자체는 모델 추론을 위해 여전히 `api.anthropic.com`으로 감).

### 핵심 개념

| 용어 | 의미 |
| :-- | :-- |
| Environment | claude.ai에서 만드는, 러너들을 묶는 이름. 세션은 환경 단위로 라우팅(개별 러너 지정 불가) |
| Environment secret | 러너가 환경에 등록하는 유일한 공유 credential("environment key"). 생성 시 1회만 표시, 365일 후 만료 |
| Runner | 배포하는 장수 프로세스. 환경에 등록해 러너 토큰을 받고 세션을 폴링 |
| Session | claude.ai·모바일·[[13 자동화와 스케줄링|routine]] 등에서 시작된 Claude Code 작업 1건. 러너가 스폰하는 자식 프로세스로 실행 |

러너는 **한 번에 한 사용자만** 서빙한다 — 처음 claim한 세션의 계정에 잠기고(`--capacity`까지 그 계정 세션만 처리), 그래서 최소 플릿 크기는 동시 활성 사용자 수다.

### 세션·러너 라이프사이클

세션: ① 여유 러너가 claim해 lease 보유 → ② 리포 clone 후 자식 프로세스 스폰 → ③ 자식이 이벤트를 HTTPS로 스트리밍, 러너 폴링이 lease 갱신 겸 heartbeat → ④ 폴링이 약 60초 끊기면 서버가 다른 러너에 requeue.

러너: `--drain-grace-sec`(기본 `0`)이 활성 세션 종료 후 동작을 정한다 — `0`이면 즉시 exit(오케스트레이터가 새 디스크로 재시작, 하드닝 권장값), 양수면 그 초만큼 잠긴 계정 큐를 더 폴링. `SIGTERM`은 [Shutdown timing](#3-프로덕션-배포-self-hosted-environments-deploy)대로 drain. 신호 없이 알려진 시각에 호스트가 죽으면 `--retire-at <epoch-seconds>`로 미리 세션을 release시킨다.

## 2. 첫 환경 세우기 (self-hosted-environments-quickstart)

전제조건: **claude.ai 쪽**은 Owner/admin이 켠 **Allow self-hosted environments** + 조직 GitHub 연결. **러너 호스트**는 Linux/macOS(Windows 미지원 — 컨테이너로 우회) + `api.anthropic.com`·`claude.ai`·git 호스트로의 아웃바운드 HTTPS + NTP 동기화된 시계(5분 이상 skew면 인증 실패) + **Claude Code v2.1.224 이상**(`claude self-hosted-runner --help`로 확인 — 구버전은 일반 `claude --help`를 출력) + Git 2.24 이상.

### 가이드 설정 vs 수동

Owner/admin 계정으로 `claude auth login` 한 머신에서 `claude self-hosted-runner setup`을 돌리면 대화형으로 환경 생성→러너 시작→등록 확인까지 안내하고 `./runner-setup/CHEAT-SHEET.md`를 남긴다. 인터랙티브 세션이 불가능한 호스트는 수동으로:

1. **환경 생성** — admin 설정에서 이름 짓고 생성, **Copy environment key**로 시크릿 복사(한 번만 표시, 365일 만료). `ccpool_...` ID는 나중에 [토큰 검증](#5-세션-신원-검증-self-hosted-environments-identity)의 `aud` 체크와 CI 테스트 dispatch에 필요.
2. **러너 시작** — 시크릿을 루트 권한 필요한 경로(예 `/etc/claude/environment-secret`)에 `(umask 077 && cat > ...)`로 셸 히스토리 없이 저장 → `--base-dir`로 체크아웃 디렉터리 지정(생략 시 `/workspace`) → `claude self-hosted-runner --environment-secret-file '...' --base-dir '...'`.
3. **등록 확인** — admin 페이지 상태가 **No runners deployed → Healthy**로 바뀜.
4. **세션 라우팅** — claude.ai/code에서 환경 선택 → 클론 가능한(호스트가 이미 접근 가능하거나 public) 리포로 시작 → 러너 로그의 `Picked up session <id>`로 확인.

세션이 뜬 뒤 어느 머신에서든 `claude -p "메시지" --cloud <session-id>`로 팔로우업을 보낼 수 있다(Anthropic 호스팅 세션과 같은 커맨드).

## 3. 프로덕션 배포 (self-hosted-environments-deploy)

러너는 **조직 내 누구든 dispatch할 수 있는, model-directed 임의 코드 실행기**다. 프로덕션 연결 전 다음을 확인한다.

### 하드닝 체크리스트

- **세션당 컨테이너**: `--capacity 1` + `--drain-grace-sec 0`으로 컨테이너 하나가 세션 하나만 처리하고 종료 시 파기. 의도적인 pre-warmed 클론 설정(`--capacity 1`에서 러너가 리포당 canonical clone을 유지·재사용하는 것) 외에는 재시작 간 파일시스템 재사용 금지, 계정 간 재사용은 절대 금지.
- **이미지에 폭넓은 credential 금지**: 장수 SSH 키·클라우드 credential 대신 [wrapper 스크립트](#4-세션-커스터마이즈-self-hosted-environments-configuration)에서 세션별로 발급. 최초 clone은 `checkout` 훅이나 `--use-anthropic-git-proxy`로.
- **environment secret을 세션 실행 호스트 밖으로**: 고정 플릿은 모든 러너 호스트가 시크릿을 들고 있어 세션 코드가 읽을 수 있다 — [on-demand runner](#on-demand-runners)를 쓰면 시크릿은 세션 코드가 절대 안 도는 오케스트레이터 호스트에만 남는다.
- **default-deny 아웃바운드 egress**: 아래 [네트워크 요구사항](#네트워크-요구사항)에 없는 호스트는 네트워크 경계에서 차단(제품이 강제 못 함 — 직접 적용).
- **최소 권한 호스트 IAM**, **클라우드 메타데이터 엔드포인트 차단**(IMDSv2 hop-limit 1, GKE Workload Identity concealment, `169.254.169.254` 명시 deny — wrapper·훅도 컨테이너를 공유하므로 함께 막힘), **러너별 파일시스템 격리**.
- **dispatch는 조직 전체 범위**: 어느 조직원이든 어느 환경에나 dispatch 가능(환경별 접근 제어 없음) — 러너 호스트를 "조직원 누구나 코드 실행 가능한 곳"으로 취급.
- **repo-settings guard**: `--confine-repo-settings <warn|enforce|off>`(기본 `warn`)로 리포에 커밋된 설정이 세션 워크스페이스 밖 쓰기·읽기(`additionalDirectories`, `permissions.allow`의 `Edit`/`Write`/`NotebookEdit`, `sandbox.filesystem.*`), 빈 아닌 `env` 블록, `sandbox.enabled: false` 같은 오퍼레이터 posture override를 시도하면 플래그.

> [!note] 조직 IP allowlist는 자체 호스팅 러너 트래픽을 기본으로 커버하지 않는다 — 네트워크 통제는 자체 경계에서.

### 네트워크 요구사항

항상 필요: `api.anthropic.com`(제어 플레인·스트리밍·추론·JWKS 등, 443/WSS) + 조직 git 호스트(443/22, `--use-anthropic-git-proxy`면 불필요). 조건부: `downloads.claude.ai`(설치/업데이트), `storage.googleapis.com`(마켓플레이스 카탈로그·Artifact), `code.claude.com`/`claude.com`(문서 조회), `*.frame.claudeusercontent.com`(Artifact tool), `raw.githubusercontent.com`(체인지로그), `registry.npmjs.org`(Node 의존성 플러그인·npx MCP). `statsig.anthropic.com`·`*.sentry.io`·`claude.ai`·`platform.claude.com`·`mcp-proxy.anthropic.com`은 **불필요**(구식 체크리스트에 남아있을 뿐).

### git 설정 3가지 중 택1

- **`--configure-git`**: Anthropic 호스팅 세션과 같은 `user.name`/`user.email` + SSH 커밋 서명(git 2.34+) 자동 설정. push credential은 별도 공급 필요.
- **이미지에 직접 설정**: `git config --system user.name/user.email`. push credential은 장수·광범위 스코프를 이미지에 굽지 말고 wrapper에서 세션별 단기 토큰 발급 권장.
- **`--use-anthropic-git-proxy`**(git 2.32+, `--capacity 1` 필수): Anthropic 프록시로 clone, 세션 자체 토큰으로 인증 — 이미지에 git credential 전혀 불필요, Anthropic 호스팅 세션과 같은 인증 경로.

`--git-host-rewrite <from>=<to>` / `--git-ssh-rewrite <host>`로 split-horizon DNS·SSH 전용 호스트 대응.

### 러너 이미지 빌드

Anthropic은 사전 빌드 이미지를 배포하지 않는다 — `claude` 바이너리(release URL에서 버전 고정 다운로드) 위에 필요한 툴체인을 얹은 자체 Dockerfile을 빌드한다. Kubernetes는 `--environment-secret-file`을 Secret으로 마운트하고 `/healthz`(기본 8080)를 liveness/readiness에 연결, `terminationGracePeriodSeconds`를 러너가 로그하는 drain 총 시간 이상으로(기본 조합 80초, K8s 기본 30초는 부족). Docker Compose는 평가용으로만(재시작해도 writable layer가 남아 하드닝 posture와 어긋남).

### Shutdown timing

`SIGTERM` → 신규 작업 중단 → `--drain-wait-sec`(기본 `0`)까지 in-flight 턴 대기 → 자식 종료 → `post-session` 훅 실행. 전체 drain은 `--session-stop-grace-sec + --drain-wait-sec + --post-session-hook-timeout-sec` + 고정 15초 + (`--push-outcome-on-release` 설정 시 +30초) — 기본값 합 80초를 러너가 시작 시 로그한다. `terminationGracePeriodSeconds`/`stop_grace_period`를 이 값 이상으로 맞추지 않으면 `post-session` 훅이 미완료 상태로 강제 종료된다.

### 알려진 이슈

커넥터(GitHub·Slack·Linear 등)는 Anthropic 쪽에서 호출돼 트래픽이 조직 네트워크를 벗어난다(막으려면 [`allowedMcpServers`/`deniedMcpServers`]([[10 MCP]]) 정책). 유휴 판정에서 제외되는 세션(끝나지 않는 백그라운드 작업·도구 내부 승인 대기)이 있어 `--release-idle-session-min`과 `--kill-session-after-min`을 항상 같이 쓴다. 세션 release·재시작 시 push 안 된 작업은 소실(대비책은 [`--push-outcome-on-release`](#레퍼런스) — 다만 resume 시 push 권한자를 검증 없이 신뢰하므로 `claude/*` ref push를 제한한 뒤 켤 것).

### 트러블슈팅

`claude self-hosted-runner doctor`(로그인 상태면 환경·러너·큐까지 조회하는 읽기 전용 진단 세션, 유일한 변경 가능 동작은 멈춘 세션 requeue). 흔한 증상: 러너 미등록(시계 skew·시크릿 만료 확인) · 세션 큐잉 정체(모든 러너가 다른 계정에 잠김 — 레플리카 추가) · pickup 직후 실패(`EACCES`는 `--base-dir` 쓰기 권한) · 브랜치 삭제로 push 실패 · 느린 시작(clone이 원인 — 위 pre-warmed 클론 설정이나 `CLAUDE_RUNNER_FETCH_DEPTH` 축소 검토) · drain 중 kill(그레이스 기간 부족).

## 4. 세션 커스터마이즈 (self-hosted-environments-configuration)

기본 러너는 clone→스폰→정리만 한다. 확장점 4가지:

### Wrapper 스크립트

`--exec-path`(또는 `SELF_HOSTED_RUNNER_EXEC_PATH`)로 세션마다 Claude Code 바이너리 대신 실행할 스크립트를 지정 — 세션별 credential 발급, 툴체인 준비, 리소스 제한 등에 쓴다. 반드시 `exec "$CLAUDE_RUNNER_CLAUDE_BIN" "$@"`로 끝내 신호·종료 코드를 전파한다(bare `&`로 백그라운드하면 stdin이 끊겨 ~30분 뒤 모든 API 호출이 `401`로 실패 — 백그라운드가 필요하면 FD 4번 이상에 stdin을 저장해 재부착). 주요 환경변수: `CLAUDE_CODE_SESSION_ACCESS_TOKEN`(세션 JWT), `CCR_SESSION_ACCOUNT_EMAIL`(서명 미검증 — 라벨링만), `CLAUDE_RUNNER_CLAUDE_BIN`, `CLAUDE_CONFIG_DIR`, `ANTHROPIC_BASE_URL`(오버라이드 금지). `decode-token` 서브커맨드로 세션 생성자 신원을 읽어 STS 등으로 스코핑된 credential을 교환하는 패턴이 표준.

### Lifecycle hooks

`--hooks-dir <path>`에 잘 알려진 이름의 실행 파일을 두면(없는 건 내장 동작으로 폴백) 러너가 세션 파이프라인 단계를 대체한다. [Claude Code 훅]([[09 훅]])과 달리 **세션 안이 아니라 러너에서** 실행된다.

| Hook | 시점 | 용도 |
| :-- | :-- | :-- |
| `checkout` | 리포당 1회, clone 대체 | 미러 clone, 아카이브에서 시드, per-session git 인증 |
| `post-session` | 세션 종료마다 | 커밋 안 된 변경 저장 — worktree 삭제 전 **유일한 기회**. abrupt termination에는 안 뜸(그건 세션 내부 `PostToolUse` 훅으로 별도 대비) |
| `command` | checkout 후 스폰 대체 | wrapper와 동일 역할, 한 hooks 디렉터리에 몰아둘 때. `--exec-path`가 있으면 그게 우선 |

### On-demand runners

고정 플릿 대신 `self-hosted-runner orchestrator`가 세션 큐잉을 감지해 `spawn-runner` 훅으로 세션당 러너를 부팅한다. environment secret이 세션 코드가 절대 안 도는 오케스트레이터 호스트에만 남고, 스폰된 러너는 세션 하나에 묶인 **1회용 work order**로 등록 — credential 위생이 고정 플릿보다 낫다. `spawn-runner` 훅 계약 4원칙: `CLAUDE_RUNNER_ORDER_ID`에 대해 멱등, 워크로드 재시도 금지, exit code 0=제출·1=재시도 가능 실패·2+=비재시도, `--expected-spawn-seconds`는 p99 부팅 시간 이상.

### MCP 서버

`claude mcp add --scope user ...`를 이미지 빌드 시(또는 러너 유저로 호스트에서) 실행하면 러너가 시작 시 `.claude.json`의 `mcpServers`만 스냅샷해 모든 세션에 시드한다(계정 상태·프로젝트 히스토리는 제외). 잠긴 플릿은 `managed-mcp.json`([[10 MCP]]), 리포 커밋 스코프는 `<repo>/.mcp.json`도 가능. `settings.json`에는 `mcpServers` 필드가 없다.

### 권한과 Stop 훅

세션에 터미널이 없어 미승인 프롬프트는 UI에서 응답할 때까지 턴을 멈춘다 — 제어 플레인이 기본 승인된 도구 세트(`Bash` 포함)를 함께 보내며, 클라우드 세션은 모드 불문 파일 편집을 사전 승인한다. wrapper나 `command` 훅에서 `--permission-mode auto`를 append하면 프롬프트를 최소화(단 [default-deny egress](#3-프로덕션-배포-self-hosted-environments-deploy) 없이는 켜지 말 것 — `Bash` 네트워크 요청도 사람 개입 없이 돈다). Anthropic 호스팅 세션은 `Stop` 훅으로 커밋·push를 유도하지만 러너는 이걸 설치하지 않으므로, 커밋 안 된 작업을 잃지 않으려면 참조 구현([[09 훅]]의 `Stop` 이벤트, uncommitted diff·unpushed commit 감지 셸 스크립트)을 러너 호스트의 `~/.claude/settings.json` + `~/.claude/hooks/`에 직접 심어야 한다.

## 5. 세션 신원 검증 (self-hosted-environments-identity)

세션 안 코드가 조직 내부 서비스를 직접 호출할 수 있으므로, 그 서비스가 "정말 내 자체 호스팅 환경의 세션인가"를 검증할 수단이 필요하다. 매 세션은 `CLAUDE_CODE_SESSION_ACCESS_TOKEN` 환경변수로 `sk-ant-cc-` 프리픽스 + `ES256` 서명 JWT를 받는다(4시간 기본·8시간 최대 수명, 갱신은 러너가 자동). 토큰은 **세션 안 임의 코드가 읽을 수 있는** bearer credential일 뿐 특정 프로세스를 증명하지 않는다는 점에 유의.

검증 순서: 프리픽스(`sk-ant-cc-`, Anthropic 호스팅용 `sk-ant-si-`와 구분) → `https://api.anthropic.com/v1/code/.well-known/jwks.json`의 JWKS로 `ES256` 서명 → `iss == "ccr"` → `aud`가 내 환경 ID(`ccpool_...`) 포함 → `ccr:role == "session_worker"` → `exp` 유효 → 신원은 `act.sub`(`user:<id>` 형식, service-key 세션은 없음)에서 읽는다. `act` 클레임은 [RFC 8693] delegation chain — 생성 유저(`act.sub`) → 러너(`act.act.sub`) → 환경(`act.act.act.sub`) 순.

wrapper처럼 세션 **안**에서 검증하려면 JWT 라이브러리 대신 `self-hosted-runner decode-token`(서명·만료만 체크, `iss`/`aud`/`role`은 직접 비교 필요, `jq -re`로 누락 클레임을 non-zero exit로 처리). 교환한 credential은 세션 하나가 필요로 하는 만큼만 스코핑하고 `exp` 이하 수명으로 제한하며, `ccr:session_id`+`jti`를 감사 로그에 남긴다 — 토큰 자체는 오프라인 검증이라 폐기 피드가 없다.

## 6. CLI 플래그·환경변수·메트릭 (self-hosted-environments-reference)

전체 표는 `claude self-hosted-runner --help`가 정본이다. 자주 참조하는 것 위주로:

| 플래그 | 기본값 | 역할 |
| :-- | :-- | :-- |
| `--capacity <n>` | `1` | 동시 세션 수(모두 같은 잠긴 계정) |
| `--base-dir <path>` | `/workspace` | 체크아웃 루트 — 환경 내 모든 러너가 **동일 값** 유지(다르면 resume 시 경로 불일치) |
| `--drain-grace-sec` / `--drain-wait-sec` | `0` / `0` | 종료 전 재폴링 유예 / in-flight 턴 대기 |
| `--confine-repo-settings` | `warn` | 리포 설정 워크스페이스-이탈 그랜트 가드 |
| `--release-idle-session-min` / `--kill-session-after-min` | `0`(비활성) | 유휴 release / 강제 종료 하드 백스톱 |
| `--push-outcome-on-release` | off | release 전 outcome 브랜치 best-effort push(`claude/*` ref push 제한 후 사용) |
| `--use-anthropic-git-proxy` | off | Anthropic 프록시로 clone(`--capacity 1`+git 2.32 필수) |
| `--lock-to-account <id>` | 미설정 | 시작 시 특정 계정에 선잠금 |
| `--health-port` | `8080` | `/healthz`·`/metrics` 포트 |

용어 매핑: 메트릭·일부 API 필드는 여전히 환경을 `pool`로 부른다(`pool_id` = 환경 ID). 오케스트레이터(`self-hosted-runner orchestrator`)는 `--environment-secret-file`·`--hooks-dir`(필수, `spawn-runner` 포함) 등 별도 플래그 세트를 쓴다. Prometheus `/metrics`로 `last_poll_age_seconds`(멈춘 러너 감지), `claude_code_self_hosted_runner_locked_account`(어느 계정에 잠겼는지), `..._session_init_duration_seconds`(clone 지연) 등을 노출.

## 7. CI에서 엔드투엔드 테스트 (self-hosted-environments-testing)

새 러너 이미지를 프로덕션에 승격하기 전, 테스트 환경에 세션을 dispatch해 응답을 읽고 팔로우업까지 왕복시키는 스모크 테스트가 CI 레시피다. 테스트 러너 호스트의 `~/.claude/`에 `Stop` 훅을 심어 매 턴의 `last_assistant_message`를 `$E2E_REPLY_DIR/<session_id>.txt`에 적재하면, 테스트 스크립트가 Anthropic API를 다시 호출하지 않고 로컬 파일만 읽어 응답을 확인할 수 있다. `claude -p "..." --cloud <session-id>`로 세션 생성·팔로우업 dispatch, 이 두 호출만 실제 API를 태운다.
