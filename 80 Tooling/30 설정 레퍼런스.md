# 30 설정 레퍼런스

허브: [[80 Tooling]]. 공식 `settings-reference` 문서(`## All settings` 색인, 총 210개 `settings.json`/`~/.claude.json` 키)를 주제별로 옮긴 **찾아보기 전용 카탈로그**다. `settings.json` 시스템 자체(스코프·우선순위·조직 배포·sandbox·환경변수·모델 구성)의 개념·절차는 [[04 설정]]에 있으니 먼저 그쪽을 읽어라 — 이 노트는 "이 키가 뭘 하고 어느 파일에 넣을 수 있는지"를 1줄로 확인하는 용도다. 이미 다른 노트가 깊게 다루는 키는 요약만 두고 링크한다.

## Scope 표기 읽는 법

| Scope 값 | 의미 |
|:---------|:-----|
| `Any file` | Managed·User(`~/.claude/settings.json`)·Project(`.claude/settings.json`)·Local(`.claude/settings.local.json`) 네 곳 어디서나 가능 |
| `Managed` | managed 소스(server-managed/MDM/`managed-settings.json`)에서만 읽힘 — user/project에 넣어도 조용히 무시(경고 없음) |
| `User or managed` | `~/.claude/settings.json` 또는 managed에서만 |
| `User, local, or managed` | user·`.claude/settings.local.json`·managed에서만(팀 공유 project 파일 제외) |
| `Global config` | `settings.json`이 아니라 `~/.claude.json`에 저장. `settings.json`에 넣으면 스키마 검증 에러 |

값이 `Managed`인데 project/user 파일에 적어도 파싱은 되고 그냥 무시된다 — 배포가 안 먹힐 때 가장 먼저 의심할 지점.

## Updates and versioning

| Key | 설명 | Scope |
|:----|:-----|:------|
| `autoUpdatesChannel` | `"latest"` 대신 `"stable"` 채널 추종 | Any file |
| `minimumVersion` | 자동 업데이트·`claude update`가 이 버전 미만을 설치 못 하게 함(다운그레이드 방지 전용) | Any file |
| `requiredMinimumVersion` / `requiredMaximumVersion` | 이 범위 밖 버전이면 **시작 자체**를 거부 | Managed |

> [!warning] `minimumVersion` ≠ `requiredMinimumVersion`
> `minimumVersion`은 업데이트만 제약한다 — 이미 설치된 낮은 버전의 실행은 막지 않는다. `requiredMinimumVersion`/`requiredMaximumVersion`은 managed 전용이며 시작 자체를 거부한다(`claude update`/`install`/`doctor`는 범위 밖에서도 항상 동작해 복구를 허용). 무효 버전 문자열은 두 키 모두 fail-open(무시)이라 잘못된 배포가 전사 락아웃을 만들지 않는다.

## 함정 노트

- **Managed 값의 침묵 실패**: Scope가 `Managed`인 키를 user/project 파일에 적어도 JSON 파싱은 통과하고 그냥 무시된다 — 경고가 안 뜬다. `permissions.*`처럼 스코프 제약 없는 형제 키와 헷갈리기 쉬운 `sshHostAllowlist`·`requiredMinimumVersion`·`disableSideloadFlags` 등이 대표적.
- **배열 병합의 예외 2개**: 대부분의 배열 설정(`permissions.allow`, `sandbox.filesystem.allowWrite` 등)은 스코프 간 concat+dedup되지만, `fallbackModel`과 (managed가 정의한 경우의) `availableModels`는 **최우선 파일이 전체를 대체**한다 → [[04 설정]] 설정 우선순위.
- **desktop 전용 vs CLI 무시**: `Tools` 섹션 3개 키와 `sshConfigs`/`sshHostAllowlist`는 데스크톱 앱만 읽고 터미널 CLI는 무시한다. Enterprise가 "설정했는데 CLI에서 안 먹힌다"고 보고하면 우선 이 표부터 확인.
- **`minimumVersion` vs `requiredMinimumVersion`**: 위 경고 박스 참고 — 이름이 비슷해 다운그레이드 방지 키를 시작 차단용으로 오해하기 쉽다.
- **보안 예외 키(project/local이 managed를 이긴다)**: `disableClaudeAiConnectors`·`isolatePeerMachines`·`remoteControlAtStartup`·`crossSessionInbound`·`useAutoModeDuringPlan`·`syncClaudeAiSkills`는 "더 엄격한 값이 어디서 오든 우선"이라는 일반 규칙의 예외다 → [[04 설정]] 설정 우선순위의 보안 예외 표.
